🧭 Why skills exist

The 4 problems that kill projects with agents—and how skills tackle each one.

What is:

A structured package (SKILL.md + scripts + refs) that the agent loads on demand to perform a specific task.

Why learn:

Without skills, you repeat context every session. With skills, knowledge is versioned, testable, and reusable.

Key concepts:

SKILL.md, frontmatter, triggers, references, scripts, single scope.

What is:

Gap between what you asked for and what the agent understood — creates silent rework.

Why learn:

It’s the #1 cause of “the agent doesn’t work.” Recognizing it early prevents hours of writing the wrong code.

Key concepts:

Ambiguity, implicit assumptions, lack of examples, vague scope.

What is:

Too many words, repetition, and noise in the prompt degrade the agent’s accuracy.

Why learn:

Compact ubiquitous language captures intent. 1 well-defined term is worth 20 lines of explanation.

Key concepts:

Token budget, noise vs. signal, shared terminology.

What is:

Code generated without live tests: it appears to work but fails in edge cases.

Why learn:

TDD with an agent turns “I hope it works” into “prove that it works.”

Key concepts:

Red/green/refactor, vertical slice, regression test.

What is:

Codebase with unclear boundaries—any change breaks things far away.

Why learn:

Agents amplify poor coupling. Architecture skills combat entropy.

Key concepts:

Coupling, boundaries, ADRs, progressive improvement.

What is:

Matt Pocock’s skill system — grill, ubiqua, tdd, architecture — chained in the workflow.

Why learn:

Understanding the map before the details speeds adoption and prevents ad hoc use.

Key concepts:

Composition, usage order, slash commands, agentic OS.

🔥 Grilling: alignment with the agent

Stop guessing what you want — let the agent ask first.

What is:

A technique where the agent asks pointed questions before coding—uncovering hidden requirements.

Why learn:

Prevents weeks of rework. 30min of grilling saves 5h of writing the wrong code.

Key concepts:

Adversarial questioning, assumptions, scope, acceptance criteria.

What is:

/grill-me attacks the raw idea; /grill-with-docs compares the plan against the project’s CONTEXT.md and ADRs.

Why learn:

Using the wrong mode wastes the grilling. Each has its own trigger.

Key concepts:

Raw idea, mature plan, reference document, ADR.

What is:

Triggers: ambiguous feature, architectural decision, team conflict, pre-PRD.

Why learn:

Knowing WHEN grilling adds value helps you avoid using it where it isn’t needed.

Key concepts:

Trigger heuristics, cost/benefit, timing.

What is:

Annotated transcript of a /grill-me session turning a vague idea into an actionable PRD.

Why learn:

See in practice what a good question looks like versus an evasive answer.

Key concepts:

Drill-down, counterexample, making assumptions explicit.

What is:

Shallow grilling, rhetorical questions, an agent that always agrees — signs of a wasted session.

Why learn:

Detecting early prevents the illusion of alignment.

Key concepts:

Sycophancy, leading questions, anchoring.

What is:

A completed grilling session becomes a PRD via /to-prd — with no loss of context.

Why learn:

Connects alignment with execution. The end of “I did the grilling and lost everything.”

Key concepts:

PRD, acceptance criteria, vertical slices, handoff.

📖 Ubiquitous Language: CONTEXT.md + ADRs

1 word instead of 20 — terminology shared between you and the agent.

What is:

Shared vocabulary across the domain, code, and agent — same term, same meaning.

Why learn:

Reduces mental translation. "Materialization cascade" is worth a paragraph of explanation.

Key concepts:

DDD, bounded context, living glossary, domain concepts.

What is:

Root document with domain, concepts, boundaries, and terms — read by the agent in every context.

Why learn:

Without CONTEXT.md, the agent relearns your domain every session.

Key concepts:

Required sections, glossary, boundaries, examples.

What is:

A short, immutable record of each architectural decision—context, options, choice, and consequences.

Why learn:

Prevents redoing an old decision without knowing it. The agent respects documented constraints.

Key concepts:

Decision, context, alternatives, status, consequence.

What is:

A real case from Matt—the term was coined once in CONTEXT.md and reused in dozens of prompts.

Why learn:

See the concrete gain from compression through vocabulary.

Key concepts:

Semantic compression, term reuse, dense intent.

What is:

Routine of updating CONTEXT.md and ADRs in every relevant PR — don’t let them turn into archaeology.

Why learn:

An outdated document is worse than no document.

Key concepts:

Docs-as-code, drift, PR gates.

What is:

Metrics comparing before and after adopting ubiquitous language — tokens, session time, bugs.

Why learn:

Justify adoption to the team with numbers, not opinions.

Key concepts:

Token spend, lead time, rework, dev NPS.

✅ Code That Works: TDD + Diagnose

Red, green, refactor — with the agent alongside. And when something breaks, /diagnose.

What is:

TDD used as a contract between you and the agent—test before code.

Why learn:

Without a test first, the agent "hallucinates" behavior. With a test, behavior is verifiable.

Key concepts:

Executable contract, feedback loop, objective criteria.

What is:

Slash command that orchestrates the TDD cycle with the agent — generates a test, runs it, implements, refactors.

Why learn:

Standardizes quality. Every feature starts with a passing test.

Key concepts:

Cycle, gates, refactoring automation.

What is:

Deliver minimum end-to-end value at a time — UI, API, database — instead of horizontal layers.

Why learn:

Enables real TDD. Each slice can be tested on its own.

Key concepts:

Slice, walking skeleton, MVP, testable increment.

What is:

A skill that guides systematic bug investigation — reproduce, minimize, hypothesize, test.

Why learn:

An intermittent bug without a method becomes an infinite loop. /diagnose enforces discipline.

Key concepts:

Hypothesis, observation, isolation, falsification.

What is:

Required sequence: reproduce the bug, reduce the case, formulate a hypothesis before touching the code.

Why learn:

Skipping a step leads to a correction that masks the bug.

Key concepts:

MCVE, bisection, falsification.

What is:

Test written from the minimized repro—ensures the bug doesn’t come back.

Why learn:

Without a regression test, you pay for the same bug 3x a year.

Key concepts:

Capture, fixture, mutation testing.

🏗️ Healthy Architecture

Get out of the mud ball without refactoring everything — agent-guided progressive improvement.

What is:

Signs: changing 1 line breaks 3 distant features, nobody knows where something lives, fear of making changes.

Why learn:

Diagnosis comes before treatment. If you don’t name the symptoms, you’ll treat the wrong symptom.

Key concepts:

Coupling, cohesion, boundaries, shotgun surgery.

What is:

A skill that scans the code, identifies hotspots, and suggests prioritized improvements.

Why learn:

Replaces "big bang refactoring" with surgical interventions.

Key concepts:

Hotspot, prioritization, safe change.

What is:

A skill that abstracts from the current file to the whole system — breaks tunnel vision.

Why learn:

A good local decision can be bad globally. Zooming out forces a systems perspective.

Key concepts:

Macros vs. micro, systems thinking, cascading impact.

What is:

Areas of the code where investing in modeling yields disproportionate returns.

Why learn:

Time is finite. Going deeper in the wrong place = polishing the sidelines.

Key concepts:

Core domain, modeling ROI, leverage.

What is:

Use the Track 1.3 documents to guide where and how to improve — the agent follows documented constraints.

Why learn:

Refactoring without a north star becomes personal taste. A documented, auditable north star.

Key concepts:

Constraints, compliance, traceability.

What is:

Codebase walkthrough from “messy” to “healthy” through small steps guided by skills.

Why learn:

Inspires confidence: you don't need to stop everything to fix it.

Key concepts:

Strangler fig, boy scout rule, short branches.

🔄 Complete workflow

From idea to merged PR — all the skills in the track, in order of use.

What is:

Command that installs all of Matt's skills in your Claude Code and prepares the environment.

Why learn:

Everything starts here. Without setup, the rest of the track won’t work.

Key concepts:

Bootstrap, dependencies, verification.

What is:

Workflow: idea → /grill-me → /to-prd. Output is a PRD ready for slicing.

Why learn:

Connects modules 1.2 and 1.6 — without this bridge, grilling becomes a lost conversation.

Key concepts:

PRD, acceptance criteria, documentation handoff.

What is:

/to-prd structures the document; /to-issues breaks it down into testable issues for execution.

Why learn:

A well-scoped issue = an unambiguous sprint.

Key concepts:

Slicing, INVEST, acceptance criteria.

What is:

A skill that decides which role (PM, dev, reviewer) the agent takes on based on the issue’s state.

Why learn:

Prevents an agent from acting as a developer when it should be reviewing, and vice versa.

Key concepts:

State machine, persona, transition gates.

What is:

Each triaged issue becomes a /tdd cycle—test, code, refactor—until green.

Why learn:

It’s where theory becomes a merge. Without TDD here, quality falls apart.

Key concepts:

Definition of done, CI gates, complete slice.

What is:

Final step: automated + human review, update CONTEXT.md/ADRs, merge.

Why learn:

Without a docs + review closeout, the cycle "leaks" and the architecture starts degrading again.

Key concepts:

Review gates, doc update, merge policy.
