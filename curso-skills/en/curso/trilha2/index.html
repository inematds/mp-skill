📦 What is mp-skill

Matt Pocock’s skills packaged for you.

What is:

Organized fork of the skill set published by Matt Pocock — packaged as a Claude Code plugin.

Why learn:

Understanding the provenance helps you trust the conventions and track upstream.

Key concepts:

Curated fork, upstream, Claude Code plugin, authorship.

What is:

Each skill is small, chainable, and adaptable—the opposite of monolithic frameworks.

Why learn:

These 3 values explain why skills outperform giant agents in real projects.

Key concepts:

Single responsibility, composition, fork-friendly.

What is:

engineering = day-to-day coding; productivity = non-coding workflows; misc = maintained but rare.

Why learn:

Knowing which bucket to look in helps you avoid wasting time digging through the repo.

Key concepts:

Categorization, discovery, intended use.

What is:

Direct comparison: GSD/BMAD/Spec-Kit are closed frameworks; mp-skill is a loose collection of skills.

Why learn:

Choosing the right tool for each problem — not everything is a skill.

Key concepts:

Framework vs. toolkit, lock-in, granularity.

What is:

TypeScript-heavy full-stack developers, solo builders, small teams that use Claude Code/Codex every day.

Why learn:

Knowing the target audience helps calibrate expectations and contribute well.

Key concepts:

Persona, real use cases, community.

What is:

Permissive license + PR-based contribution flow — open to new skills and improvements.

Why learn:

Know what you can redistribute, adapt, and send back without friction.

Key concepts:

License, PR, CODEOWNERS, attribution.

🗂️ Repository structure

Each folder has a clear purpose.

What is:

Bucket with coding skills: grill-me, tdd, diagnose, improve-codebase-architecture, etc.

Why learn:

It's where 80% of daily use happens — it's worth getting to know each one.

Key concepts:

Core skills, gateway, slash commands.

What is:

Bucket with process skills: handoff, statusline, audit, planning — outside the editor.

Why learn:

Process skills save the most time and context between sessions.

Key concepts:

Workflow, handoff, session.

What is:

Skills that are maintained but used sporadically — they don’t deserve prominence, but they don’t deserve to be deleted either.

Why learn:

Find the right skill at the right time. It’s worth reviewing misc quarterly.

Key concepts:

Long tail, minimal maintenance.

What is:

personal = owner's setup; in-progress = drafts; deprecated = retired — none appear in the README/plugin.json.

Why learn:

Understanding why skills disappear from the index avoids confusion when contributing.

Key concepts:

Lifecycle, draft, promotion, deprecation.

What is:

docs/ stores references; scripts/ contains utilities; CLAUDE.md provides organization rules for the repo itself.

Why learn:

Without understanding CLAUDE.md, you break conventions when adding a new skill.

Key concepts:

Project, automation, and documentation rules.

What is:

plugin.json lists published skills; README lists each skill with a link to SKILL.md.

Why learn:

Every new skill needs to be added to both—or it will be invisible in the plugin.

Key concepts:

Manifest, index, publication gates.

⚙️ Installation and setup

30 seconds from zero to your first /grill-me.

What is:

Have Claude Code or Codex installed, with a compatible plan and a working shell.

Why learn:

Without the right runtime, skills don’t even appear — debugging that later is frustrating.

Key concepts:

Runtime, plan, shell, plugin host.

What is:

Single command that downloads and registers the plugin in Claude Code/Codex.

Why learn:

It's the official way — other installation methods break during updates.

Key concepts:

npx, registry, marketplace, plugin.

What is:

The interactive wizard lets you choose which skills to enable—starting with engineering skills is recommended.

Why learn:

Too many skills for an agent = noise. Initial curation is worth its weight in gold.

Key concepts:

Curation, scope, selective activation.

What is:

Slash command that creates an initial CONTEXT.md, configures defaults, and validates triggers.

Why learn:

Skips a lot of manual setup and ensures skills trigger at the right times.

Key concepts:

Bootstrap, defaults, triggers.

What is:

mp-skill GitHub Issues with labels (bug, skill-request, docs) — public demand queue.

Why learn:

Using the right label speeds up the response and prevents duplicate issues.

Key concepts:

Triage, labels, priority, community.

What is:

Checklist: list the skills in the agent, run /grill-me in a dummy repo, and check the logs.

Why learn:

Validating early prevents you from discovering that installation failed only when you try to use it.

Key concepts:

Smoke test, dry run, logs.
