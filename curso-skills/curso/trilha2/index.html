2.1 ~25 min

📦 O que é o mp-skill

Skills do Matt Pocock empacotadas pra você.

O que e:

Fork organizado do conjunto de skills publicado por Matt Pocock — empacotado como plugin Claude Code.

Por que aprender:

Entender a procedência ajuda a confiar nas convenções e a acompanhar upstream.

Conceitos-chave:

Fork curado, upstream, plugin Claude Code, autoria.

O que e:

Cada skill é pequena, encadeável e adaptável — o oposto de frameworks monolíticos.

Por que aprender:

Esses 3 valores explicam por que skills vencem agentes-gigantes em projetos reais.

Conceitos-chave:

Single responsibility, composição, fork-friendly.

O que e:

engineering = dia-a-dia de código; productivity = workflow não-código; misc = mantido mas raro.

Por que aprender:

Saber em qual bucket procurar evita perder tempo cavando o repo.

Conceitos-chave:

Categorização, descoberta, intenção de uso.

O que e:

Comparação direta: GSD/BMAD/Spec-Kit são frameworks fechados; mp-skill é coleção solta de skills.

Por que aprender:

Escolher a ferramenta certa para cada problema — não tudo é skill.

Conceitos-chave:

Framework vs toolkit, lock-in, granularidade.

O que e:

Devs full-stack TypeScript-heavy, builders solo, times pequenos que rodam Claude Code/Codex todo dia.

Por que aprender:

Conhecer o público alvo ajuda a calibrar expectativas e contribuir bem.

Conceitos-chave:

Persona, casos de uso reais, comunidade.

O que e:

Licença permissiva + fluxo de contribuição via PR — abertura para skills novas e melhorias.

Por que aprender:

Saber o que pode redistribuir, adaptar e enviar de volta sem atrito.

Conceitos-chave:

Licença, PR, CODEOWNERS, atribuição.

🗂️ Estrutura do repositório

Cada pasta tem um propósito claro.

O que e:

Bucket com skills de código: grill-me, tdd, diagnose, improve-codebase-architecture, etc.

Por que aprender:

É onde 80% do uso diário acontece — vale conhecer cada uma.

Conceitos-chave:

Core skills, gateway, slash commands.

O que e:

Bucket com skills de processo: handoff, statusline, audit, planning — fora do editor.

Por que aprender:

Skills de processo são as que mais economizam tempo e contexto entre sessões.

Conceitos-chave:

Workflow, handoff, sessão.

O que e:

Skills mantidas mas usadas esporadicamente — não merecem destaque, não merecem deletar.

Por que aprender:

Achar a skill certa em momento certo. Vale revisar misc trimestralmente.

Conceitos-chave:

Long tail, manutenção mínima.

O que e:

personal = setup do dono; in-progress = drafts; deprecated = aposentados — nenhum aparece no README/plugin.json.

Por que aprender:

Entender por que skills somem do índice evita confusão ao contribuir.

Conceitos-chave:

Ciclo de vida, draft, promoção, deprecation.

O que e:

docs/ guarda referências; scripts/ tem utilitários; CLAUDE.md dá regras de organização do próprio repo.

Por que aprender:

Sem entender CLAUDE.md você quebra convenções ao adicionar skill nova.

Conceitos-chave:

Regras de projeto, automação, documentação.

O que e:

plugin.json registra skills publicadas; README lista cada skill com link para SKILL.md.

Por que aprender:

Toda skill nova precisa entrar nos dois — caso contrário fica invisível no plugin.

Conceitos-chave:

Manifesto, índice, gates de publicação.

⚙️ Instalação e configuração

30 segundos do zero ao primeiro /grill-me.

O que e:

Ter Claude Code ou Codex instalado, com plan compatível e shell funcional.

Por que aprender:

Sem o runtime correto, skills nem aparecem — debugar isso depois é frustrante.

Conceitos-chave:

Runtime, plan, shell, plugin host.

O que e:

Comando único que baixa e registra o plugin no Claude Code/Codex.

Por que aprender:

É o caminho oficial — outras formas de instalar quebram em update.

Conceitos-chave:

npx, registry, marketplace, plugin.

O que e:

Wizard interativo deixa escolher quais skills habilitar — recomendado começar pelas engineering.

Por que aprender:

Skills demais pra agente = ruído. Curadoria inicial vale ouro.

Conceitos-chave:

Curadoria, escopo, ativação seletiva.

O que e:

Slash command que cria CONTEXT.md inicial, configura defaults e valida triggers.

Por que aprender:

Pula muito setup manual e garante que skills disparem nos gatilhos certos.

Conceitos-chave:

Bootstrap, defaults, triggers.

O que e:

GitHub Issues do mp-skill com labels (bug, skill-request, docs) — fila pública de demanda.

Por que aprender:

Usar a label certa acelera resposta e evita issues duplicadas.

Conceitos-chave:

Triage, label, prioridade, comunidade.

O que e:

Checklist: listar skills no agente, rodar /grill-me em um repo dummy e checar logs.

Por que aprender:

Validar cedo evita descobrir que a instalação falhou só na hora do uso.

Conceitos-chave:

Smoke test, dry-run, logs.
