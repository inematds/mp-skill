Por qué existen las skills

Las Skills son paquetes de instrucciones cargados bajo demanda que Claude Code (o Codex) activa solo cuando el contexto lo requiere. En vez de amontonar reglas enormes en el system prompt y esperar que se sigan, describes la habilidad una vez, en un solo lugar, y el agente la carga cuando la necesita.

Matt Pocock formalizó este patrón para resolver cuatro problemas muy específicos que encuentra todo ingeniero que usa LLM en serio. Este curso cubre todo en 3 rutas: fundamentos, anatomía del repositorio y uso avanzado.

Los 4 problemas que resuelven las skills

1

Desalineación

El agente hace casi lo que quieres, pero con convenciones incorrectas: nombres de variables, estilo de pruebas, estándar de commits. Las Skills fijan el "cómo" antes de que el agente decida por su cuenta.

2

Verbosidad

Vuelves a explicar las mismas reglas en cada sesión. Una skill bien hecha acaba con ese ciclo: basta con el trigger adecuado y carga todo de una vez.

3

Código roto

El agente genera código que parece correcto pero no se ejecuta: falta validación, falta la verificación de tipos, falta el paso de prueba. Las skills codifican la lista de control de calidad.

4

Ball of mud

CLAUDE.md se convierte en un archivo enorme de 2000 líneas: nadie lo lee completo y nadie sigue sus instrucciones. Las skills dividen este monolito en piezas que se cargan solo cuando son relevantes.

Para quién es este curso

👥 Público objetivo

  • • Ingenieros que usan Claude Code o Codex en el día a día
  • • Líderes de equipo que quieren estandarizar el workflow con LLM
  • • Quienes ya probaron CLAUDE.md y quedaron frustrados con el resultado

📋 Requisitos previos

  • • Cuenta de Claude Code (o Codex CLI) instalada
  • • Cómodo con la línea de comandos y Git
  • • Haber tenido al menos una sesión real con un agente

🎯 Qué vas a aprender

  • • Anatomía de una skill: SKILL.md, activadores, alcance
  • • Cómo escribir descripciones que se activen en el momento adecuado
  • • Workflow de Matt: del borrador a la skill publicada
  • • Ejemplos reales: handoff, revisión de código, depuración

POR QUÉ ESTO IMPORTA

No estás aprendiendo a usar una herramienta.
Estás aprendiendo la ingeniería de la próxima década.

Los agentes de IA ya forman parte del flujo de trabajo diario de los ingenieros. La pregunta ya no es "si" — é cómo vas a aprovecharlo. Y quien todavía trate al agente como un autocompletado glorificado se quedará atrás de quienes aprendieron a construir sistemas de razonamiento reutilizables.

Este curso te da las 3 cosas que nadie enseña: cómo alinear al agente antes de que se equivoque, cómo combinar skills en workflows que aportan valor real, e cómo crear un lenguaje ubicuo que hace que todo tu equipo — humano y máquina — hable de lo mismo.

No se trata de escribir mejores prompts. Se trata de construir el sistema que hace innecesarios los mejores prompts.
